## 비교축 3: 이벤트 참가 신청 (RSVP)

### 비교표

| 항목 | 소모임 | Lu.ma | Geneva | Partiful | サクスク | CircleApp |

## 안티패턴 (절대 차용 금지)

### 안티패턴 1: 모달 → 페이지 이동 → 다시 모달 중첩 플로우
- **사례:** RSVP 모달 클릭 → 로그인 페이지 이동 → 다시 이벤트 페이지 복귀 → 다시 RSVP 모달 열기
- **문제:** 맥락 소실로 사용자 이탈률 급등. redirect_to 파라미터로 자동 복귀 처리 필수
- **기존 메모:** 이미 project-feature-benchmark의 안티패턴 2번과 동일 — 중복 주의

### 안티패턴 2: 채팅 도입 즉시 LINE 대체 선언
- **사례:** "K CLUB 채팅 개설 시 LINE 그룹 탈퇴 요청"
- **문제:** 일본 학생의 LINE 의존도가 극히 높음. 강제 전환은 이탈 유발. LINE 연락처 링크를 앱 내 채팅과 병존시키며 점진 전환 유도 권장
- **적용:** 채팅 도입 초기에는 "LINE / K CLUB 채팅 중 선택" 구조 유지

### 안티패턴 3: 참가자 실명 + 사진 전면 공개 (익명 옵션 없음)
- **사례:** Partiful의 전면 소셜 공개 (RSVP 즉시 실명+프로필 전체 노출)
- **문제:** 일본 학생은 익명 선호 성향이 강함 (Twitter 닉네임 문화). 실명 강제 공개는 참가 신청 자체를 기피하게 만듦
- **적용:** 참가자 목록은 닉네임 + 아바타만 표시. 실명 노출은 개인 설정에서 opt-in으로 처리

### 안티패턴 4: 별점 / 평점 시스템 도입
- **사례:** Meetup의 그룹 ★4.5 / 698 리뷰
- **문제:** 학생 운영자(서클 대표)가 별점 조작·낮은 평점에 민감하게 반응. 운영진 기피 및 서클 이탈로 이어짐. 기존 P0 메모리에 이미 안티패턴으로 기록됨
- **대체:** inquiry_count(문의 수) + 레포트 게시 수 + "最近N日前に活動" 텍스트로 활동성 간접 표현
