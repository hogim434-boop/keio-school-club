## 0. 이 문서를 어떻게 읽어야 하나요? (초보자용 안내)

코딩 입문자도 따라갈 수 있도록 다음 순서로 읽으면 좋습니다.

1. **「1. 프로젝트 개요」** — K CLUB이 뭘 만드는지 한 줄로 이해

5. **「5. 의존성 체인」** — 어떤 Task 가 어떤 Task 를 먼저 끝내야 시작할 수 있나
6. **「7. 기술 부채·리스크 관리」** — 작업하면서 빠지면 안 되는 함정들

### 0-1. Task 카드 읽는 법

각 Task 는 다음 8개 항목으로 구성됩니다.

| 항목             | 뜻                                                             |
| ---------------- | -------------------------------------------------------------- |
| **Phase**        | 1-1 / 1-2 / 1-3 / 1-4 / 1-5 / 1-6 / 1.5 중 하나                |
| **우선순위**     | High (필수 길목) / Med (있어야 정상) / Low (있으면 좋음)       |

| **관련 기능 ID** | PRD 5장의 F0XX 번호 (PRD 본문과 매핑)                          |
| **산출물**       | 끝나면 코드베이스에 새로 추가/변경되는 구체적 파일·테이블·기능 |
| **검증 기준**    | 「이게 되면 Task 끝났다」 라고 판단하는 측정 가능한 조건       |

### 0-2. 우선순위 색상 약속

- **High** = Phase 의 길목 (이게 막히면 후속 Task 가 줄줄이 막힘)
- **Med** = 길목은 아니지만 Phase 안에서 반드시 포함됨
- **Low** = 시간 남으면 챙기는 정도 (베타 후 보완 가능)

## 1. 프로젝트 개요

### 1-1. K CLUB 한 줄 정의

**K CLUB은 게이오生의 「동아리 가입 검토」 도구다. 가입 결정 순간까지 K CLUB이 책임지고, 가입 後엔 LINE에 깔끔하게 인계한다.**

### 1-2. 시간차 비전 (M3, PRD 1·4장)

```
[1단계 탐색]  웹    — 발견·동아리 상세·이벤트 열람 (익명 OK)
   ↓
[2단계 검토]  앱    — 気になる·運営に問い合わせる·マイページ (로그인 + 푸시)
   ↓
[3단계 가입 後]  LINE — 그룹 채팅·친목 (K CLUB 의도된 졸업)
```

K CLUB은 LINE을 **대체하지 않습니다**. LINE이 본질적으로 못 하는 영역(횡단 비교·갤러리 영구 보관·1:1 비공개 문의·이벤트 캘린더)을 채울 뿐입니다. 단체 채팅·실시간 그룹 메시지는 의도적으로 도입하지 않습니다.

### 1-3. 핵심 기능 4축

- **A축 발견** — 횡단 검색·카테고리 큐레이션·신환 시즌 큐레이션 (`F010·F011·F012·F014`)
- **B축 동아리 상세 (단순화, v2.2)** — 프로필 + 갤러리 + 이벤트 섹션 + 메인 CTA 「運営に問い合わせる」 (`F020·F021·F026·F041·F050`)
- **C축 이벤트·캘린더·빡센 관리** — 이중 모드 RSVP·정원·웨이팅 자동 관리·승인 게이팅·CSV·변경 알림·취소 통보 (`F030~F049`)
- **D축 운영진 DM** — 실시간 비대칭 모델·그룹 인박스·신고·차단·cooldown·온라인 상태 (`F050~F058`)

### 7-4. 기술 부채 관리 원칙

- **`cacheComponents` 의도적 OFF 유지** [[cachecomponents-disabled-on-purpose]] — 전역 재활성화 금지. 쿼리 단위 `unstable_cache` + `revalidateTag()` 만 사용.
- **DB 트리거는 최소화** — `F045` 자동 승격 (T-023) 1개에만 사용. 나머지는 Server Action에서 처리.
- **마이그레이션 1파일 = 1개념** — 한 파일에 테이블 + RLS + GRANT + 인덱스 묶지 말고 분리 (롤백 용이성).
- **임시 더미 데이터 (`lib/dummy/`)** — Phase 1-3 종료 시까지만 사용. Phase 1-6 (T-044) 검수 단계에서 모두 실 데이터로 교체 확인.
